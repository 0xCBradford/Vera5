# Vera5

Browser extension for on-demand IOC detection and triage on `http://` and `https://` pages you browse. Visible-text IOC detection runs by default; optional link attribute scanning is off until you enable it in Settings. Scans, enrichment, scoring, export, investigation sessions (including session timelines, **Investigation replay**, and a text-first **Investigation notebook** with typed fragments), same-page **Appeared alongside** co-occurrence, cross-session **Appeared across sessions** clusters, IOC collections, operator macros, inspectable local **noise rules** (learned from explicit labels or optional import), local **known-good lists** (CDN/SaaS and similar curated patterns with visible **Known benign** / **Known internal** labels), and portable **threat profiles** / **settings packs** (workflow preferences without API keys) run locally—you bring your own API keys; Vera5 does not operate a shared enrichment cloud. Overlay and tray can show **Previously appeared with** when local relationship edges exist; automatic write from **Scan page** into that store is not wired today (see **Limitations**). **Local page profile** classifies the active tab from URL and bounded DOM signals only (no page upload or cloud fingerprinting) to tune tray ordering, default export templates, analyst preset defaults, and optional playbook suggestions. **Quiet mode** (off by default) blocks outbound live vendor enrichment while preserving local detection, cached enrichment display, and attributed pivot links. **Chromium** is the primary install target (`extension/dist/`); an experimental **Firefox** Manifest V3 build ships as `extension/dist-firefox/`. Optional **local AI summary** stays on `127.0.0.1`; the extension also includes an off-by-default client bridge for a compatible localhost enrichment service, but this repository does not ship that server.

## Quick start (install and keys)

**Install (developers and testers)**

```bash
cd extension
npm install
npm run build
```

Load **`extension/dist/`** in Chrome (manifest **0.1.0**). See [Load unpacked (Chrome)](#load-unpacked-chrome) for load steps, packaging, and a manual walkthrough.

**Firefox (experimental):** From `extension/`, run `npm run build:firefox`, then load **`extension/dist-firefox/manifest.json`** as a temporary add-on in Firefox. See [Load temporary add-on (Firefox)](#load-temporary-add-on-firefox) and [docs/browser-support.md](docs/browser-support.md).

On **first install**, Vera5 opens **Settings** once for a four-step **Install quick start** wizard (Welcome → optional live-source API keys → enrichment control → trust defaults). Step 2 offers key fields for **AbuseIPDB**, **OTX**, **URLScan.io**, **GreyNoise**, **Shodan**, and **Censys** (API ID). **Censys** also needs a separate secret under **API keys** on the full **Settings** page; **VirusTotal** keys are configured there too. Completing the wizard keeps **manual-only enrichment** on and **auto-scan** off unless you change them in the wizard or under **Scanning**.

**Bring your own API keys (BYOK/BYOA)**

Vera5 does not ship vendor credentials or proxy enrichment through maintainer infrastructure.

1. Open **Vera5 Settings** from the extension workspace (Chromium side panel or Firefox toolbar popup).
2. Enter your own **AbuseIPDB**, **OTX**, **URLScan.io**, **GreyNoise**, **Shodan**, **Censys**, and/or **VirusTotal** API keys (masked in the UI). **Censys** requires an API ID and a separate secret field.
3. Enable those sources under **Enrichment Sources**. Keys stay in `chrome.storage.local` on your machine.
4. Leave **Manual-only enrichment** on (default) until you are ready for automatic vendor fetches when you open the triage overlay.

**Optional localhost bridge:** The extension includes an off-by-default client for a compatible service at `127.0.0.1:8765`; no backend server implementation is included in this repository. Leave **Use local backend** off unless you separately operate a compatible service. The expected boundary is documented in [docs/local-mode.md](docs/local-mode.md).

**Optional local AI summary:** Off by default under **Local AI Summary** in settings. Requires a ready enrichment card and a model you run on `127.0.0.1`. Behavior, grounding rules, and Ollama model naming: [docs/ai-summary.md](docs/ai-summary.md), [SECURITY.md — Optional local AI summary](SECURITY.md#optional-local-ai-summary-llm). See **Optional local AI summary** in [What works today](#what-works-today).

The extension does not read API keys from a repository `.env` file. Optional root `.env.example` is for repository tooling only.

**Privacy summary**

- Scans and detection run locally on pages you open.
- Live enrichment sends **only the selected indicator value** to vendors **you** enable—not full page content.
- Optional **link attribute scanning** (off by default) reads allowlisted link and attribute values locally only when you enable it under **Trust & consent**—never full pages or attribute dumps to Vera5.
- Optional **local AI summary** (off by default) sends normalized enrichment JSON to `127.0.0.1` only when you enable it and click **Generate summary**—not page HTML or API keys.
- No maintainer telemetry, crash reporting, or Vera5-operated network endpoints by default.
- Trust controls (pre-query notices, domain policy, internal asset lists, **quiet mode**) can block vendor calls before they leave the browser.
- **Investigation replay** plays back local session events only—no screen/video capture, no upload of replay data, and no live vendor re-enrichment during step-through.
- **Appeared across sessions** clusters IOC sets from your local investigation sessions only—no global threat graph, no Vera5-operated correlation cloud, and no upload of cluster data.
- **Previously appeared with** (relationship memory) stays in local storage only—relationship-edge records on your browser profile when present; no global graph database, no cross-user relationship intelligence, and no upload of relationship graphs.
- **Noise rules** stay in local storage only—created from explicit watchlist opt-in or optional import; no telemetry, no cloud learning, and no automatic suppress without a user-visible rule.
- **Known-good lists** stay in local storage only—curated inspectable entries you maintain or import; no Vera5-hosted known-good feed, no cloud goodware or global reputation API, and no hidden score that overrides composite risk.
- **Investigation notebook** fragments stay in local storage only—typed text notes you author on indicators, sessions, or page context; no cloud notebook sync, no shared team notebooks, and no screenshot or screen-capture upload.
- **Threat profiles** and **settings packs** are local JSON handoffs only—never API keys; Vera5 does not host a profile marketplace or auto-update feed.

Details: [Privacy and keys (BYOK/BYOA)](#privacy-and-keys-byokbyoa), [SECURITY.md](SECURITY.md), [docs/security-model.md](docs/security-model.md).

## Limitations

What Vera5 does **not** do today:

| Limitation | Detail |
|---------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Browser support** | **Chromium** (primary): Chrome, Edge, Brave, and similar Manifest V3 browsers. **Firefox** (experimental): temporary add-on from `extension/dist-firefox/` only—not distributed on Mozilla Add-ons (AMO). Safari/WebKit is not supported. |
| **Install path** | **Chromium:** unpacked load from `extension/dist/` (manifest **0.1.0**). Package a zip with `.\scripts\package-extension.ps1` at the repository root (`release/vera5-0.1.0.zip`). Chrome Web Store listing draft: [docs/store-listing.md](docs/store-listing.md)—submission is separate operator work. **Firefox:** build `extension/dist-firefox/` and load `manifest.json` as a temporary add-on (`about:debugging`); package with `.\scripts\package-extension-firefox.ps1` (`release/vera5-firefox-0.1.0.zip`). Temporary add-ons do not persist across full browser restarts. |
| **Live enrichment** | Live HTTPS API queries when you enable **AbuseIPDB**, **OTX**, **URLScan.io**, **GreyNoise (community)**, **Shodan**, **Censys**, or **RDAP/WHOIS** (indicator-type coverage in **What works today**). All live calls dispatch through the bundled **connector registry** in the background worker—no maintainer enrichment relay. **RDAP/WHOIS** is keyless (domain indicators only). **VirusTotal** saves your API key locally and provides pivot links; live HTTPS enrichment is not enabled in the extension today. Other registry entries remain pivot- and settings-only. Stable registry ids for each source: [docs/api-integrations.md](docs/api-integrations.md). |
| **Backend** | No Vera5-operated enrichment relay, shared team workspace, or cloud sync for sessions, collections, macros, replay transcripts, notebook fragments, noise rules, known-good lists, relationship-memory edges, threat profiles, settings packs, or keys. The extension ships only an off-by-default client bridge for a separately operated compatible service at `127.0.0.1:8765`; this repository does not include the server. If the bridge is enabled but unavailable, Vera5 falls back to in-extension connectors. |
| **Investigation notebook** | Local typed text fragments only (**Observation**, **Tag**, **Conclusion**, **Hypothesis**)—no cloud notebook sync, no shared team notebooks, and no full document-management surface. Bodies are text or markdown-lite; screenshot and screen-capture authoring are out of scope. |
| **Threat profiles** | Local JSON export/import and built-in profiles only—no Vera5-hosted profile marketplace or auto-update feed. Profiles never include API keys; import rejects secret-like fields. Profiles cannot bypass pre-query disclosure, domain deny, quiet mode, or internal asset gates. |
| **Investigation replay** | Local step-through and markdown transcripts only. No screen or video capture, no cloud-hosted replay sharing, and no live vendor re-enrichment while you step through (highlight + narrative playback). |
| **Cross-session correlation** | Local **Appeared across sessions** list/adjacency in the tray only. No force-directed graph canvas, no global threat map, no ML relationship inference, and no automated detection verdict from co-occurrence alone. In-product copy states **Correlation ≠ causation**. Correlation pack markdown/JSON appendix builders exist as a library contract only—there is no **Export correlation pack** control in the workspace or overlay today (same honesty pattern as **Workspace snapshot UI**). |
| **Relationship memory** | Local **Previously appeared with** panels on the overlay and tray only (entity partners such as IP, domain, hash when edges exist)—not a force-directed graph, global threat map, or ML entity-resolution layer. Advisory co-occurrence only (**Correlation ≠ causation**); not automated actor/campaign attribution. **Clear all relationship memory** removes stored edges and does not delete investigation sessions. Edge builders and `relationshipEdges` storage ship with the extension; automatic persistence from **Scan page** / enrich into that store is not wired in the background worker today, so panels stay empty until edges exist in local storage. |
| **Noise rules** | Inspectable local pattern rules only (exact, regex, domain suffix, CIDR)—no opaque ML weights, no Vera5-operated training, and no automatic suppress without an explicit label opt-in or optional import you review. Matching IOCs move to the tray **Suppressed** section and show a deprioritized overlay badge; detection still finds them unless you enable **Hide suppressed indicators from scan** (off by default). Domain policy deny still wins over noise rules for live enrich and auto-scan. |
| **Known-good lists** | Local curated entries only (domain, IP, CIDR, ASN, hash-prefix)—informational **Known benign** / **Known internal** (or custom) labels, not a silent safe verdict or cloud goodware score. No Vera5-hosted known-good feed and no global reputation API. Optional **Skip outbound vendor enrich on known-good match** is off by default; domain deny and quiet mode still win. Labels do not override composite risk. Options **Known-good lists** exports and manages stored entries today; there is no dedicated **Import list** control on that card (JSON/CSV import exists as a storage import path for validated handoff files, including the optional `examples/known-good-cdn-saas-starter.json` starter—never auto-applied). |
| **Local AI summary** | No bundled or cloud LLM—opt-in only. Requires a user-operated OpenAI-compatible server on `127.0.0.1`. No endpoint or model fields in Settings today (fixed `127.0.0.1:11434` path and `"model":"local"` in requests). Narrative markdown is unverified and does not replace the local composite risk score or per-source vendor rows. |
| **Page coverage** | Content scripts on `http://` and `https://` only. Default detection reads visible text nodes (not scripts or hidden input values); stops after 2,500 text nodes per scan. Optional **Scan link attributes for IOCs** (off by default) adds a separate capped pass over allowlisted `href`, `src`, `data-url`, `data-href`, `data-src`, and `cite` values when you enable it in Settings. |
| **Data sent to vendors** | Indicator values you choose to enrich—not full pages, attachments, or clipboard dumps. |
| **Scoring** | Advisory labels computed locally; not a vendor verdict. Blended **/100** needs at least two parseable OK source results. Per-source **connector confidence metadata** chips (when shown) are informational only—they do not change the composite score, reasoning chain, or export score fields. **Known-good** match labels are triage context only and do not override composite risk. See **Composite risk score** in [What works today](#what-works-today) for extended-indicator behavior. |
| **Connector confidence metadata** | Informational tier, freshness, and source-class chips on multi-source hover cards only (single-source cards omit the **Sources** section). No Vera5-operated metadata feed, no hidden second score, and no Vera5 **malicious** verdict from chips. Per-connector overrides import through **settings packs** or full **Settings Backup** JSON in Options—[connector profile JSON](docs/export-artifacts.md) is a library contract only, not a separate Options export control (distinct from portable **threat profiles**). |
| **Automation** | Pull request CI runs browser smokes on Playwright Chromium with mocked vendors—it does not replace manual checks on an unpacked Chromium build or a Firefox temporary add-on before you rely on the extension in production triage. Optional local Firefox smokes (`npm run test:e2e:firefox`) cover temporary add-on load and a scan → enrich → export path on a fixture page; they do not gate merge today. |
| **Workspace snapshot UI** | Versioned JSON export, markdown bundle, Obsidian vault zip, and merge/replace import (with confirmation and secret-field rejection) are implemented as library builders only—there are no **Export workspace snapshot** or **Import workspace snapshot** controls in the extension workspace today. Use **Session export** (including **Session notebook** markdown from session-attached fragments), **Collection export**, **Timeline appendix export**, and **Settings packs** for operator handoff. Artifact contracts: [docs/export-artifacts.md](docs/export-artifacts.md). |
| **README images** | Brand mark at the top of this README (`docs/vera5-logo-mark.png`). No embedded product screenshots yet. Capture guide: [docs/screenshots.md](docs/screenshots.md). |

More detail: [docs/architecture.md](docs/architecture.md), [docs/api-integrations.md](docs/api-integrations.md), [docs/contributors/testing.md](docs/contributors/testing.md) (E2E scope and limits).

## Operator surfaces

On `http://` and `https://` tabs, day-to-day triage uses the surfaces below.

| Surface | Where it runs | Role |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **On-page overlay** | Content script on the active page | Triage card on scanned highlights: trust details, enrichment, per-source **connector confidence metadata** chips (reliability tier, freshness policy, source class) on multi-source rows, pivots, free-text **Analyst notes**, **Investigation notebook** (typed fragments on Indicator / Session / Page scopes; a non-empty legacy note migrates to an **Observation** fragment on read when that IOC has no fragments yet), optional **AI summary (local, unverified)** when enabled, **Appeared alongside**, **Previously appeared with** (when local relationship edges exist), **Label**, **Pin**, **Session timeline**, **Save to collection…**, copy, and export. When a **noise rule** matches, a deprioritized badge and matched-rule summary appear with a link to open that rule in Settings. When a **known-good** entry matches, a **Known benign** / **Known internal** (or custom) badge and matched-entry provenance appear with a link to that entry in Settings; if skip-enrich policy blocked live enrich, the card shows **Enrichment skipped (known-good policy)**. Open by clicking a highlight or with **Enter** / **Space** on a focused highlight; **ArrowDown** / **ArrowUp** move between highlights. See **What works today** for field-level behavior. |
| **Command palette** | Content script on the active page | **Ctrl+Shift+K** / **Cmd+Shift+K** opens a searchable list of core actions plus palette-enabled built-in and custom macros. Choose a command with the keyboard or mouse; **Esc** closes the palette. |
| **Selection context menu** | Browser context menu on selected text | **Enrich selection with Vera5** resolves one indicator and opens the overlay. **Pivots** opens nested Authoritative / Community intel sites (with **Open all** per category); the site list filters to the current selection’s indicator type and to sites enabled under **Settings → Pivots**. **Case** covers Open Analyst Lens, Pin, Label, and Save to collection. **Run macro on selection** lists context-enabled macros. Enrich and macro paths use the same content-script runner and trust gates; pivot opens are user-initiated vendor tabs (not background API enrichment). |
| **Extension workspace** | Chromium **side panel** (toolbar click) or Firefox **toolbar popup** / optional **sidebar panel** | Extension on/off, scan and selection actions, **Quiet mode** status, **Page profile**, investigation sessions (including **Notebook fragments** search for the active session), **Session timeline** export, **Investigation replay** (step-through and transcript export), history, **Detected indicators** tray with **Appeared alongside**, **Appeared across sessions**, **Appeared with** (when local relationship edges exist), collapsed **Suppressed** section for noise-rule matches, known-good matches sorted below active investigation IOCs, **Run macro…** per row and **Run macro on filtered…**, collections, source operations, **Settings**, and **Permissions**. Chromium keeps the panel open while you switch tabs. |
| **Settings (options) page** | Dedicated options tab for keys, enrichment toggles, scanning, **Pivots** (right-click menu category/site visibility), cache, trust controls, **Noise rules**, **Known-good lists**, **Cross-session correlation**, **Relationship memory**, **Operator Macros**, and **Settings Backup** (full backup, key-free **settings packs**, and portable **threat profiles** with built-in apply). Create and reorder custom macros, configure palette/tray/context triggers and steps, or export/import custom macro packs without keys. See **Options page** in [What works today](#what-works-today) for the full control list. |

Keyboard shortcuts: **Ctrl+Shift+Y** / **Cmd+Shift+Y** triggers **Scan page**; **Ctrl+Shift+K** / **Cmd+Shift+K** opens the **command palette**. After **Scan page** (shortcut or palette), focus the extension workspace to refresh the **Detected indicators** tray for that tab.

See [Local mode — what runs where](docs/local-mode.md) for extension-only runtime, the optional localhost bridge boundary, and local storage; [Typical triage flow](docs/analyst-workflows.md) for scan, overlay, and enrichment on a page tab.

## What works today

| Capability | Behavior |
|------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Install** | **Chromium:** `npm run build` in `extension/`, then load `extension/dist/` unpacked in Chrome. **Firefox (experimental):** `npm run build:firefox`, then temporary add-on load—see [Load temporary add-on (Firefox)](#load-temporary-add-on-firefox). |
| **Install quick start** | First-run wizard in **Settings**: install checklist, optional live-source API keys (saving a key can auto-enable that source), **Manual-only enrichment** (recommended on), auto-scan summary, and pre-query notice choice (**Show pre-query notices (recommended)** or skip). Finishing the wizard persists safe defaults (manual-only on, auto-scan off). |
| **Command palette** | **Ctrl+Shift+K** / **Cmd+Shift+K** on a page tab opens a filterable command list. Core commands and palette-enabled macros share one registry; search macros by name, id, tag, or **macro**. **Enter** runs the highlighted command; **Esc** closes the palette. |
| **Selection context menu** | With indicator text selected, right-click under **Vera5**: **Enrich selection with Vera5** opens the overlay and starts manual enrichment when resolved; **Pivots** lists type-matched Authoritative / Community sites (plus **Open all**), filtered by **Settings → Pivots**; **Case** offers Open Analyst Lens, Pin, Label, and Save to collection; **Run macro on selection** lists context-enabled macros. Domain policy, internal asset lists, quiet mode, and pre-query disclosure apply to every enrich step. |
| **Operator macros** | Versioned, local-only playbooks stored in `chrome.storage.local`. Built-ins: **CTI Deep Check** (enrich → Markdown export → attributed pivots) and **DFIR Triage** (enrich → queue related tray IOCs → append a note template). Custom macros support `enrich`, `exportMarkdown`, `openPivot`, `applyNoteTemplate`, and `queueRelatedIocs` steps with palette, tray, and context-menu triggers. Create, edit, duplicate, delete, and reorder them under **Operator Macros** in Settings. Custom macro packs export/import as validated JSON without built-ins or API keys. Enrich trust failures abort later steps with an explicit message; live enrich work is capped per run to prevent unbounded vendor fan-out. |
| **Investigation history** | Local list (up to **50** entries) of recently enriched indicators with page origin and timestamp in the extension workspace **Investigation history** section. Click a row to scroll to the page highlight and reopen the overlay when you are on the **same tab origin** and the IOC is still highlighted (rescan if needed). Palette **Open history** focuses the same section. Rows linked to the active investigation session show **Linked to this session**. **Clear history** (with confirmation) removes all entries on this browser profile. History records after completed enrichment only—no cloud sync. |
| **Selection scan** | On dense dashboard exports, highlight a table row or panel and use **Scan selection** in the extension workspace to detect indicators in visible text only within that range—without rescanning the full page. Link attribute scanning applies to **Scan page**, not selection scans. |
| **Selection enrich** | Select indicator text (including inside a scanned highlight) and use **Enrich selection** (extension workspace, command palette, or context menu) to open the overlay and request enrichment for that value when it resolves to a single supported indicator. |
| **Keyboard triage** | Highlights are focusable (`Tab`). **ArrowDown** / **ArrowUp** move to the next or previous highlight in document order (wraps at the ends); from page focus after scan, **ArrowDown** selects the first highlight and **ArrowUp** the last. **Enter** / **Space** on a focused highlight opens the overlay and moves focus to the first focusable control in the panel (**Copy Indicator**, **Copy defanged** when shown, or session controls such as **Pin** when a session is active). **Escape** closes the overlay; after a keyboard-opened overlay, focus returns to the highlight. Arrow keys do not triage while focus is inside the overlay panel. |
| **IOC tray** | Scrollable **Detected indicators** list in the extension workspace with per-type filter chips and count summary (for example `12 indicators · 2 URL · 1 SHA256 · 1 SHA1 · 2 MD5 · 2 CVE · 2 IP · 1 DOM · 1 EML` on `sample-alert.html`, or additional `ASN` / `CIDR` / `PATH` / `ONION` chips when those types appear on a page). Type chip order follows the active **Page profile** when classified. Indicators matching active **noise rules** move under a collapsed **Suppressed** section (still listed for triage; not a detection verdict). Known-good matches sort below indicators tied to the active investigation session and show a **Known benign** / **Known internal** (or custom) badge with matched-entry provenance. Click a row to open its on-page overlay, expand **Why detected?**, save it to a collection, or choose **Run macro…**. **Run macro on filtered… (N)** applies a tray-enabled macro to the current type-filter subset in list order with a shared live-enrich budget. Palette copy/export commands use the same filter state. |
| **On-page highlights** | After scan, detected indicators with a mapped text node get an inline underline, type badge, and **›** enrich control when highlighting is enabled. Attribute-only matches (when link attribute scanning is on) can appear in the tray without a page highlight. |
| **Detection provenance** | Each match stores a rule id and source text hint from the scan. **Why detected?** on the overlay and IOC tray explains the indicator type, detection reason, surrounding context, and any overlapping matches dropped during dedupe. When **Scan link attributes for IOCs** is enabled, markup-sourced matches include attribute provenance (for example `href on <a> element: …`). |
| **Defang and refang** | Detects common defanged forms in visible text (`hxxp`/`hxxps`, bracket dots such as `[.]`, bracket scheme separators). Match values are refanged for enrichment, pivots, and default copy; highlights still cover the original on-page text. When forms differ, use **Copy defanged** or **Copy refanged** on the overlay header. |
| **Composite risk score** | When enrichment returns per-source results, a **Risk score** section shows a locally computed advisory band (**Unknown**–**Critical**, with **/100** when a blended composite is available), a **How this score was computed** panel (ordered per-source lines from normalized summaries, or an explicit empty state when no parseable OK summaries exist), and a **Sources disagree** note when source bands diverge materially. Blended **/100** labels parse summary patterns from **AbuseIPDB**, **OTX**, **URLScan.io**, and **GreyNoise** today; **Shodan**, **Censys**, and **VirusTotal** rows can appear on the card without contributing to the composite. Requires at least two parseable OK enrichment results for a blended **/100** label; with one OK source, expect **Unknown risk**, an insufficient-data notice, and a single reasoning line when that summary is parseable. **Email address**, **ASN**, **IPv4 CIDR**, **file path**, and **onion domain** indicators do not produce blended **/100** labels—enabled live connectors skip those types with explicit copy, so expect **Unknown risk** after enrichment while **Recommended next pivots** remain available. If every enrichment source is disabled, the section shows **Risk score unavailable** with settings guidance. Footer disclaimers may appear when scoring applies. Per-source metadata chips (see **Connector confidence metadata**) never alter this section. |
| **Live enrichment** | **AbuseIPDB** (IPv4), **OTX** (IPv4, domain, URL, MD5, SHA1, SHA256, CVE), **URLScan.io** (domain, URL), **GreyNoise (community)** (IPv4), **Shodan** (IPv4, domain), **Censys** (IPv4 only), and **RDAP/WHOIS** (domain only, no API key) when enabled in extension-only mode (**Use local backend** off) and **quiet mode** is off. The background worker routes each enabled live source through the **connector registry**; UI and content scripts never call vendors directly. The optional localhost client bridge supports a separately operated compatible service for AbuseIPDB IPv4 and falls back to in-extension connectors when unavailable. **VirusTotal** accepts a saved API key and pivot links but does not perform live HTTPS enrichment today. Only the selected indicator value is sent to enabled vendors; a runtime allowlist blocks undeclared outbound fetch before network I/O. |
| **Connector registry** | Thirteen enrichment sources share one registry inside the extension bundle: stable ids (`abuseipdb`, `otx`, `urlscan`, `rdap_whois`, …), per-source capability metadata (live vs pivot-only, API key requirement), default **connector confidence metadata** (reliability tier, freshness policy, source class), and a single background dispatch path. Connectors ship in the package—no hosted marketplace or remote code loading. Private fork pattern: [docs/local-connector-stub.md](docs/local-connector-stub.md). Architecture: [docs/architecture.md — Connector SDK](docs/architecture.md#connector-sdk). |
| **Connector confidence metadata** | On multi-source hover cards, each source row in the **Sources** section can show small informational chips for **reliability tier** (for example **Community**, **Authoritative**, **Pivot only**), **freshness policy** (**Standard**, **Volatile**, **Stable**), and **source class** (**Community** vs **Authoritative**)—including live, cached, skipped, and pivot-only rows. Chip tooltips state the labels are informational only and do not change the composite risk score or replace per-source live results. Missing fields omit chips without blocking enrichment. Defaults ship with the registry; optional per-connector overrides import through **settings packs** or full **Settings Backup** JSON in Options—never API keys. Connector profile JSON can carry the same overrides as a library contract ([docs/export-artifacts.md](docs/export-artifacts.md)); there is no separate Options export control for connector profiles (distinct from portable **threat profiles**). Overrides do not alter composite scoring or case export score fields. Detail: [docs/api-integrations.md — Connector confidence metadata](docs/api-integrations.md#connector-confidence-metadata-hover-card), [docs/analyst-workflows.md — Interpreting connector confidence metadata](docs/analyst-workflows.md#interpreting-connector-confidence-metadata). |
| **Settings packs** | Export a **settings pack** (`vera5-settings-pack.json`) from **Settings Backup** to share connector toggles, cache TTL, domain policy, analyst mode, and optional **connector confidence metadata** overrides per registry id—never API keys. **Import settings pack** shows a field-by-field diff preview before you apply; stored API keys on the profile stay unchanged. Disable individual types under **Indicator types** in settings. Private-space IPv4 (RFC1918, loopback, link-local) is omitted by default; enable **Include private-space IPv4 addresses** when needed. Stops after 2,500 text nodes per scan. Detector grammar and negative fixtures: [extended indicator detector spec](docs/phase2-ioc-detector-spec.md). |
| **Build** | **Chromium:** `npm run build` emits `dist/`, then runs `verify:dist` and `verify:security`. **Firefox:** `npm run build:firefox` emits `dist-firefox/` with the same bundles and runs `verify:firefox-manifest`, `verify:dist` (Firefox dist), and `verify:security:firefox`. Shared checks cover extension-page CSP, outbound fetch allowlist, no `eval`, production logging hygiene, redacted test fixtures, and empty credential placeholders in root `.env.example`. `npm run check` runs lint and unit tests. `npm run audit:prod` checks production dependencies (same blocking policy as CI). Optional `npm run test:e2e:critical` (Chromium) and `npm run test:e2e:firefox` run browser smokes on unpacked builds with mocked vendor HTTP (no live API calls in CI). |

## Configuration flow

1. Build and load the extension: **Chromium** — [Load unpacked (Chrome)](#load-unpacked-chrome); **Firefox (experimental)** — [Load temporary add-on (Firefox)](#load-temporary-add-on-firefox). On first install, complete the **Install quick start** wizard in **Settings** (four steps: Welcome checklist, optional API keys, enrichment control, trust defaults). Before upgrading an existing install, export **Settings Backup** JSON if you want a file rollback after storage migration.
2. Open **Vera5 Settings**, enter keys for **AbuseIPDB**, **OTX**, **URLScan.io**, **GreyNoise**, **Shodan**, **Censys**, and/or **VirusTotal** when you want those sources configured, enable **RDAP/WHOIS** when you want keyless domain registration context, and enable the live connectors you need. Live HTTPS responses come from enabled live connectors through the bundled registry (**URLScan.io**: domain and URL only; **GreyNoise** and **Censys**: IPv4 only; **Shodan**: IPv4 and domain; **RDAP/WHOIS**: domain only; **VirusTotal**: pivot links only today).
3. **Optional:** Enable **Use local backend** only when you separately operate a compatible service at `127.0.0.1:8765`; this repository does not provide that server. Leave the toggle off for normal extension-only enrichment.
4. **Optional:** Enable **Enable local AI summary** when you run an OpenAI-compatible model on `127.0.0.1` (see [docs/ai-summary.md](docs/ai-summary.md) for the default URL and `"model":"local"` naming). Enrich an indicator to **ready**, open the overlay, and use **Generate summary**.
5. Under **Trust & consent**, set pre-query notices, domain policy, internal asset lists if needed, **quiet mode** when you need cache-and-pivot-only triage without outbound vendor API calls, and an analyst workflow preset when useful. Optionally set **Treat this site as …** when a host should always use a specific page profile (for example force **Generic page** on an internal portal). Leave **Scan link attributes for IOCs** off unless you need markup-only IOCs on trusted CTI paste hosts—enable only after the first-enable consent dialog.
6. Under **Scanning** and **Enrichment cache**, choose indicator types (including email, ASN, CIDR, file path, and onion when needed), optional private-space IPv4, cache lifetime, **Manual-only enrichment** (default on), and optional auto-scan.
7. Triage on page tabs via the overlay, extension workspace tray, command palette, or context menu. Under **Operator Macros**, use the built-in playbooks or create local step sequences and enable only the palette, tray, or context triggers you need. Use palette **Open history** or **Source health** when you need recent enrichments or quota context.
8. Use **Investigation session** (including **Notebook** fragments on the overlay, workspace **Notebook fragments**, **Session timeline** filters, **Export timeline appendix**, and **Investigation replay** step-through with **Copy transcript** / **Download transcript**) and **IOC collections** for case tracking and ticket handoff exports. Under **Export session**, prefer full **Copy Markdown** when you want the **Session notebook** section; leave **IOC export only** unchecked unless you intentionally omit notebook text. Under **Settings → Cross-session correlation**, adjust retention and overlap merge when you use **Appeared across sessions**; use **Clear all clusters** when you want to reset stored clusters without deleting session history. Under **Settings → Relationship memory**, adjust retention for **Previously appeared with** edges; use **Clear all relationship memory** to wipe those edges without deleting investigation session history.
9. **Optional noise rules:** Under **Noise rules**, review learned rules, import the optional SOC dashboard starter or a teammate JSON/CSV handoff (add-only or replace-all with confirmation), and export rules without API keys. Prefer explicit **Label** opt-in on the overlay when you want Vera5 to learn a rule from Benign / Internal / Suppress false positive. Domain deny under **Trust & consent** still blocks enrich on denied hosts.
10. **Optional known-good lists:** Under **Known-good lists**, review category matching toggles, edit or delete stored entries, and use **Export list JSON** for handoff without API keys. Leave **Skip outbound vendor enrich on known-good match** off until you want matching indicators to skip live vendor calls. Matches are visible **Known benign** / **Known internal** labels only—not a silent safe verdict. An optional CDN/SaaS starter ships at [`examples/known-good-cdn-saas-starter.json`](examples/known-good-cdn-saas-starter.json) (never auto-applied); Options does not expose an **Import list** control today—JSON/CSV import is a local storage import path used by tests and handoff tooling.
11. **Optional profile handoff:** Export a **settings pack** from **Settings Backup** on one browser profile and import it on another after reviewing the diff preview—API keys stay local to each profile. Packs can include per-connector confidence metadata overrides (tier, freshness, source class labels) without changing scoring behavior on import. For richer workflow bundles (connectors, pivots, export template, analyst mode, quiet mode), use **Export threat profile** / **Import threat profile** or apply a built-in (**SOC Triage**, **Malware Research**, **CTI Hunting**)—profiles never carry keys; read the pre-import warning and cancel if you do not want changes. Threat profiles supersede overlapping pack fields when both are in play; cache TTL and domain policy stay pack- or manually controlled unless you change them. For investigation artifacts operators can use today, combine **Session export**, **Timeline appendix export**, **Investigation replay** transcript copy/download, and **Collection export**; full-workspace snapshot JSON import/export has no workspace UI controls today (see **Workspace snapshot UI** under Limitations). See [docs/analyst-workflows.md — Settings packs and threat profiles](docs/analyst-workflows.md#settings-packs-and-threat-profiles) and [docs/export-artifacts.md](docs/export-artifacts.md).

13. **Appeared across sessions:** After at least two investigation sessions have scanned overlapping IOC sets (for example `sample-alert.html` then `sample-malware-blog.html`, or the same fixture in a second session), open a shared tray indicator and expand **Appeared across sessions**—confirm other-session drill-down (title, truncated URL, date) or the empty-state copy when data is insufficient, the **Correlation ≠ causation** note, and (on the current tab scan) the link into **Appeared alongside**. In **Settings → Cross-session correlation**, confirm retention days and overlap merge controls; optional **Clear all clusters** should empty the tray expanders without removing **Recent sessions**.
14. **Previously appeared with:** On the overlay and tray, confirm the **Previously appeared with** / **Appeared with** expander appears only when local relationship edges exist for that indicator (empty or hidden when the store has no partners). When edges are present, expand the list and confirm related hash/domain (or other entity) rows, prior-session drill-down when available, and advisory **Correlation ≠ causation** language—not a graph canvas. In **Settings → Relationship memory**, confirm the retention control and edge count; **Clear all relationship memory** (confirm the dialog) should empty the panels without removing **Recent sessions**. Note: automatic edge write from **Scan page** is not wired in the background worker today—expect empty panels on a fresh profile until edges exist in local storage.
15. After a completed enrich on the fixture page, open **Investigation history** (or palette **Open history**) and click the row—confirm the page scrolls to the highlight and the overlay reopens with the same cached enrichment. Try palette **Source health** and confirm **Source operations** shows per-source status, cache counts, and **Vendor quota** hints.
16. **Optional local AI summary:** Enable **Enable local AI summary**, enrich an indicator to **ready**, click **Generate summary**, and confirm markdown under **AI summary (local, unverified)** with the panel disclaimer; verify claims match per-source rows and **Risk score** on the card. Requires a model on `127.0.0.1`—see [docs/ai-summary.md](docs/ai-summary.md).
17. **Optional link attribute scanning:** Leave **Scan link attributes for IOCs** off and confirm SOC dashboard fixtures (`sample-splunk-export.html`, `sample-security-onion-alert.html`) match documented tray counts. Enable the toggle after the consent dialog, open `sample-malicious-attribute-iocs.html`, **Scan page**, and confirm attribute-only defanged URLs appear with **Why detected?** attribute provenance; turn the toggle off again on sensitive hosts. See [docs/soc-validation-fixtures.md — Link attribute scanning](docs/soc-validation-fixtures.md#link-attribute-scanning-opt-in).
18. **Quiet mode:** With at least one cached enrichment on a fixture IOC, enable **Quiet mode** (palette **Toggle quiet mode** or **Trust & consent**). Confirm the in-page banner, toolbar badge **Q**, and workspace **Quiet mode** header. **›** live enrich on an uncached indicator should block with a clear message; cached rows should still show **Cached** badges. **Recommended next pivots** should still open vendor tabs when you click them. Toggle quiet mode off and confirm live enrich works again.
19. **Page profile override:** On `sample-splunk-export.html`, open **Trust & consent → Treat this site as …**, choose **CTI platform**, save, and rescan. Confirm the workspace badge shows **Override**, the effective profile is **CTI platform**, and **Reset to auto-detect** restores **SOC dashboard**. Overrides persist across reload until cleared.
20. **Operator macros:** On `sample-alert.html`, select the exact text of one detected IOC and run **CTI Deep Check** from the command palette. In the tray, use **Run macro…** on one row or **Run macro on filtered…** for a type subset and choose **DFIR Triage**. Under **Operator Macros** in Settings, create a three-step custom macro with the palette trigger, save it, and confirm it appears by name in the same command palette. Trust blocks must show an explicit abort and stop later steps.
21. **Noise rules:** On `sample-splunk-export.html` (or another dense SOC fixture), **Scan page**, open a noisy highlight such as `8.8.8.8`, set **Label** to **Suppress false positive**, and confirm the learn-noise-rule dialog. Confirm the tray moves matching rows under **Suppressed** and the overlay shows the deprioritized badge. In **Settings → Noise rules**, edit or disable the rule and confirm the tray updates without reloading the page. Optionally **Import SOC dashboard starter**, review the merge dialog, and confirm rules appear locally with no outbound training or sync traffic in DevTools Network.
22. **Known-good lists:** Under **Settings → Known-good lists**, confirm category toggles, **Export list JSON**, and the optional skip-enrich toggle (default off). With known-good entries already stored on the profile, open a page that includes a matching CDN IP/domain and a non-listed IOC, **Scan page**, and confirm the match shows **Known benign** / **Known internal** with matched-entry provenance while the non-listed IOC still enriches and scores. Optionally enable **Skip outbound vendor enrich on known-good match**, enrich the CDN match, and confirm **Enrichment skipped (known-good policy)** with no vendor Network call (cache-cold preferred). Note: Options has no **Import list** button today; the optional starter file is [`examples/known-good-cdn-saas-starter.json`](examples/known-good-cdn-saas-starter.json).

## Privacy and keys (BYOK/BYOA)

- API keys, enrichment cache, operator macro definitions, analyst notes, investigation notebook fragments, investigation sessions (including session timeline events that power **Investigation replay**, same-page co-occurrence indexes, cross-session **Appeared across sessions** clusters, and **Previously appeared with** relationship edges), investigation history, IOC collections, **noise rules**, and **known-good lists** stay in local extension storage by default on both Chromium and Firefox; Vera5 does not host enrichment infrastructure.
- Enrichment requests go from the background worker directly to vendors you enable when **Use local backend** is off. The optional localhost client bridge is off by default and requires a separately operated compatible service; no backend server is included in this repository.
- **Local AI summary** (off by default) sends normalized enrichment export JSON from the content script to `127.0.0.1` only—via `http://127.0.0.1:8765/summarize` when **Use local backend** is on and reachable, otherwise to `http://127.0.0.1:11434/v1/chat/completions` (fixed default; no endpoint field in Settings). No page HTML, vendor keys, or Vera5-operated LLM relay.
- Settings export omits API keys unless you include them. **Settings packs** and **threat profiles** never include API keys; import rejects files with secret field names. Workspace snapshot artifact builders apply the same redaction rules when used (library contract only—no workspace export/import UI). Pre-migration backup snapshots and migration artifacts stay in local extension storage only—they are not uploaded.
- Manual-only enrichment is on by default.
- Pre-query disclosure runs before the first vendor call when notices are enabled; domain policy, internal asset lists, and **quiet mode** can block enrichment without sending indicator values. Selection enrich and every macro `enrich` step use the same gates; blocked macro runs stop before later steps.
- No maintainer telemetry, crash reporting, or Vera5-operated network endpoints by default.
- Scans and detection run locally. Enrichment sends only the selected indicator value to declared vendor API hosts you enable. **Page profile** classification uses URL and bounded DOM signals on the active tab only—no page HTML upload, cloud fingerprinting, or cross-tab page content collection. **Appeared alongside** uses the local tab scan snapshot only—no page HTML leaves the browser for same-page adjacency. **Appeared across sessions** clusters IOC sets from local investigation session memory only—no global threat graph, no Vera5-operated correlation cloud, and no upload of cluster or pack data. **Previously appeared with** relationship edges stay local only—no global graph database, no cross-user relationship intelligence, and no upload of relationship graphs. **Noise rules** are created only from explicit watchlist opt-in or optional local import—no telemetry, no Vera5-operated training, and no upload of rule contents or page HTML. **Known-good lists** are curated local entries only—no Vera5-hosted known-good feed, no cloud goodware or global reputation API, and no hidden score that overrides composite risk; optional skip-enrich never bypasses domain deny or quiet mode. **Investigation notebook** fragments stay local only—no cloud notebook sync, no shared team notebooks, and no screenshot/screen-capture upload. **Investigation replay** reads the local session timeline only—no screen/video capture, no replay upload, and no live vendor re-enrichment during step-through; transcript copy/download is user-initiated. With **Scan link attributes for IOCs** on, allowlisted attribute values are processed locally under the same trust gates—no attribute dumps or page HTML leave the browser. Composite risk labels and reasoning chains are computed locally from vendor summaries; **connector confidence metadata** chips are registry-defined labels only—no cloud metadata feed and no effect on the composite score. Raw JSON panels redact sensitive key fields before display. Production bundles omit sensitive `console` output. **Open live URL** uses your browser only after you confirm; Vera5 does not fetch or proxy that navigation.

## Security

Security posture is local-first: your keys stay in browser storage, enrichment uses bring-your-own API credentials, and there is no Vera5-operated enrichment relay. The optional localhost client bridge is disabled by default and has no bundled server in this repository.

| Control | What it does |
|-------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`npm run verify:security`** | Runs after every Chromium production build. Checks extension-page CSP and packaged assets, enforces background outbound fetch allowlists for declared connector modules (registry-backed live connectors), rejects `eval` / remote dynamic import, scans production bundles for sensitive logging, enforces redacted test fixture placeholders, and verifies root `.env.example` credential variables are empty. Local AI summary POSTs are validated separately in unit tests (content script, localhost-only). |
| **`npm run verify:security:firefox`** | Same security checks against `dist-firefox/` after `npm run build:firefox` (no additional telemetry hosts; Mozilla `data_collection_permissions.required: ["none"]` enforced by `verify:firefox-manifest`). |
| **`npm run audit:prod`** | Fails on moderate-or-higher vulnerabilities in production dependencies (React runtime shipped in `dist/`). CI uses the same blocking policy; full `npm audit` warns only on devDependencies. |
| **Browser E2E smokes (CI)** | Pull requests run `npm run test:e2e:critical` on unpacked `dist/` in headless Chromium with mocked enrichment HTTP—no live vendor API calls. CI also builds `dist-firefox/` as an artifact; optional local `npm run test:e2e:firefox` covers temporary add-on load and scan → enrich → export on a fixture page. |
| **Gitleaks** | Repository secret scan on pull requests and pushes to `main` (`.github/gitleaks.toml`). Run locally from the repo root: `gitleaks detect --source . --config .github/gitleaks.toml`. |
| **Outbound allowlist** | Live enrichment HTTPS calls go only to configured vendor connector endpoints; undeclared hosts are blocked before network I/O in the background worker. Localhost enrich POSTs to `127.0.0.1:8765` are allowed only when **Use local backend** is on. Local AI summary POSTs stay on `127.0.0.1` (direct endpoint or backend **`/summarize`**) when **Enable local AI summary** is on; the content script rejects non-localhost summary URLs. |
| **Trust gates** | Domain policy, internal asset lists, manual-only enrichment (default), pre-query disclosure, and **quiet mode** limit accidental vendor queries on sensitive pages. **Noise rules** deprioritize matching indicators in the tray and overlay only—they never authorize enrich or auto-scan on a host blocked by domain policy. |
| **Hostile-page DOM** | Default detection reads visible text nodes only. When **Scan link attributes for IOCs** is enabled, allowlisted attribute values are read locally under the same trust gates as visible-text IOCs. Overlay UI uses `textContent` for untrusted strings; see [Malicious page DOM confusion](docs/security-model.md#malicious-page-dom-confusion). |

Security hardening checklist and operator browser confirmation steps: [docs/security-model.md](docs/security-model.md#security-hardening-review-checklist). Vulnerability reporting: [SECURITY.md](SECURITY.md). Do not commit API keys or `.env` files. Root `.env.example` documents optional repo-side tooling variables with empty credential placeholders; configure extension API keys under **Vera5 Settings**.
