Credential reset procedure

Generic documentation fixture for page-context fallback checks. Values below are public test data from examples/sample-iocs.txt.

When to use this runbook

Use this procedure when an employee reports suspicious sign-in activity from a known lab address such as 192.0.2.1 or when passive DNS shows an unexpected hostname like example.com on a managed asset. These strings support detection regression only—they are not active incident indicators.

Steps

  1. Confirm the account lockout ticket references the correct user.
  2. Capture any related URL the user clicked, for example https://example.com/login.
  3. Reset credentials and record the related file hash d41d8cd98f00b204e9800998ecf8427e if malware cleanup is required.
  4. Notify the service desk alias analyst@corp.example.com.
